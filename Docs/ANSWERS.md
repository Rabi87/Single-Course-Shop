# أجوبة الأسئلة السابقة

## السؤال 1: شرح المشروع وكيفية البدء به وغاية الملفات

### نظرة سريعة على المشروع  
هذا المشروع هو **متجر لدورة تدريبية واحدة** مبني باستخدام **PHP + MySQL + Bootstrap**. يتيح لك بيع دورة واحدة، إدارة سلة الشراء، قبول الدفع عبر رمز QR، وإرسال إشعار واتساب تلقائي للمدير عند إتمام الطلب. كما يحتوي على لوحة تحكم آمنة للأدمن لتعديل الدورة، إضافة صور، وإدارة الطلبات.

### كيف تبدأ بالعمل عليه؟

1. **استيراد قاعدة البيانات**  
   - الملف: `sql/schema.sql` يحتوي على جميع الجداول والبيانات الأولية.  
   - إذا كنت تستخدم Docker (كما هو موضح في الملاحظات)، نفّذ:  
     ```bash
     docker exec -i php-mysql-docker-mysql-1 mysql -u root -proot_secure_password_123 < sql/schema.sql
     ```  
   - أو استورد الملف يدوياً عبر phpMyAdmin (`http://localhost:8081`).

2. **إنشاء حساب الأدمن**  
   - افتح المتصفح على: `http://localhost:8080/courses/setup.php`  
   - أدخل بيانات الأدمن ثم احذف ملف `setup.php` لأسباب أمان.

3. **تعديل الإعدادات العامة**  
   - افتح `includes/config.php` وعدّل القيم التالية حسب بيئتك:  
     - `ADMIN_WHATSAPP_NUMBER` → رقم واتساب المدير (بدون +).  
     - `QR_IMAGE_PATH` → مسار صورة رمز QR الخاص بالدفع.  
     - `CURRENCY` → رمز العملة (مثلاً: SAR، USD).  
     - `BASE_URL` → رابط الموقع (مثلاً: `http://localhost:8080/courses`).

4. **إضافة الصور**  
   - صورة الدورة: `assets/images/course.svg`  
   - رمز QR للدفع: ضع صورتك في `assets/qr/qr-code.svg` (إذا لم يوجد الملف سيتم توليد رمز افتراضي).

5. **تشغيل المشروع**  
   - تأكد أن خادم الويب (Apache/Nginx) يشير إلى المجلد `courses`.  
   - افتح `http://localhost:8080/courses/index.php` لرؤية المتجر.

### ما الغاية من كل ملف ومجلد؟

| المسار | الغاية | لماذا تم إنشاؤه؟ |
|--------|--------|-------------------|
| `index.php` | الصفحة الرئيسية: عرض الدورة وزر “أضف إلى السلة”. | نقطة الدخول للزوار؛ يُظهر تفاصيل الدورة ويبدأ عملية الشراء. |
| `cart.php` | عرض سلة الشراء وتعديل الكميات أو حذف العناصر. | يحتاج المستخدم إلى مراجعة طلبه قبل الدفع. |
| `checkout.php` | نموذج بيانات العميل (الاسم، البريد، الهاتف، إلخ). | لجمع المعلومات المطلوبة لإتمام الطلب وإرسال إشعار واتساب. |
| `order-success.php` | رسالة نجاح بعد إتمام الطلب وتأكيد رقم العملية. | يوفر تغذية راجعة明確ة للمستخدم بعد الدفع. |
| `admin/` | لوحة تحكم آمنة للأدمن. | يحتاج صاحب المتجر إلى إدارة الدورة، الصور، والطلبات دون الحاجة إلى تعديل الكود مباشرةً. |
| `assets/` | الملفات الثابتة: الصور، الأنماط، الجافاسكريبت. | يحافظ على تنظيم المحتوى المرئي ويتيح تحديثه بسهولة (مثلاً تغيير صورة الدورة أو رمز QR). |
| `includes/` | ملفات مشتركة تُدرج في صفحات متعددة (مثلاً `config.php`, دوال مساعدة، الاتصال بقاعدة البيانات). | يتجنب تكرار الكود ويجعل الصيانة أسهل؛ أي تعديل هنا ينعكس على جميع الصفحات التي تستدعيها. |
| `sql/` | ملفات قاعدة البيانات (`schema.sql` ربما يحتوي أيضًا على بيانات أولية). | لتسهيل نشر المشروع على بيئات جديدة؛ مجرد استيراد الملف يُنشئ الجداول المطلوبة. |
| `logs/` | ملفات سجلات الأخطاء أو العمليات (إذا تم تفعيل التسجيل). | مفيد لتصحيح الأخطاء ومراقبة النشاط في بيئة الإنتاج. |
| `.htaccess` | قواعد إعادة كتابة عناوين URL وتحسين الأمان (مثلاً منع الوصول المباشر لبعض المجلدات). | يجعل الروابط أكثر نظافة ويعزز الحماية دون تعديل إعدادات الخادم يدوياً. |
| `setup.php` | سكريبت一次ية لإنشاء حساب الأدمن (يُحذف بعد الاستخدام). | يُوفّر طريقة آمنة لإنشاء أول مستخدم administrador دون الحاجة إلى التعامل مع SQL مباشرةً. |
| `process-payment.php` و `cart-ajax.php` | معالجات AJAX لتحديث السلة دون إعادة تحميل الصفحة ومحاكاة عملية الدفع (من خلال رمز QR). | تحسين تجربة المستخدم عبر تفاعلات سلسة وبلا إعادة تحميل. |
| `README.md` و `PRD.md` و `TODO.md` | توثيق المشروع، المتطلبات، وقائمة المهام. | يساعد أي مطور جديد على فهم النطاق، كيفية الإعداد، وما يبقى ليتم إنجازه. |

### المتطلبات التي قادت إلى إنشاء هذه الملفات  

- **need to sell a single course** → صفحات المتجر (`index.php`, `cart.php`, `checkout.php`, `order-success.php`).  
- **need to manage the course and orders** → لوحة تحكم (`admin/` مع ملفات مثل `login.php`, `index.php`, `edit-course.php`, `orders.php`).  
- **need to store data safely** → ملف قاعدة البيانات (`sql/schema.sql`) + إعدادات الاتصال في `includes/`.  
- **need to customize payment and notifications** → ملفات الإعداد (`includes/config.php`) ومجلد `assets/` للصور (QR، صورة الدورة).  
- **need security** → تضمين حماية CSRF، prepared statements، تجريد المخرجات (إدراج هذه الإجراءات في الملفات المشتركة داخل `includes/`).  
- **need easy deployment** → ملفات التوثيق (`README.md`, `PRD.md`) والتعليمات لتسهيل الإعداد على أي بيئة (Docker أو خادم عادي).

## السؤال 2: كيف أبدأ المشروع من الصفر (خطة/أهداف دون كتابة كود)

### 1️⃣ تحديد المتطلبات بوضوح  
| الفئة | الأسئلة الأساسية | المخرجات |
|-------|-------------------|----------|
| **الوظيفة الأساسية** | ما الذي سيبيعه المتجر؟ (دورة واحدة) <br> ما هي إجراءات الشراء؟ (عرض → سلة → بيانات العميل → دفع via QR → إشعار واتساب → صفحة نجاح) | قائمة مهام المستخدم النهائي (Visitor flow). |
| **لوحة التحكم** | ما الذي يحتاجه الأدمن لتعديل الدورة، صورة، سعر، حالة الطلبات؟ | وظائف CRUD للدورة + إدارة الطلبات + إعدادات (رقم واتساب، مسار QR، عملة). |
| **السلامة** | كيف نحمي من حقن SQL، XSS، CSRF؟ | إدراج إجراءات وقائية في كل طبقة (PDO+Prepared، htmlspecialchars، tokens). |
| **الأداء/التجربة** | هل نحتاج تفاعلات AJAX لتحديث السلة دون reload؟ | قرار باستخدام Vanilla JS + Fetch/AJAX. |
| **النشر** | أي بيئة ستُشغل المشروع؟ (Docker، LAMP، shared hosting) | اختيار stack وتوثيق متطلبات الإعداد. |

**النتيجة:** مستند متطلبات functional + non‑functional (يمكن أن يكون Markdown بسيطًا).

### 2️⃣ تصميم بنية البيانات (Database Schema)  
1. **جدول الدورات** (`courses`) – يحتوي على: id، title، description، price، image_path، created_at.  
2. **جدول المستخدمين / الأدمن** (`admins`) – id، username، password_hash، created_at.  
3. **جدول الطلبات** (`orders`) – id، course_id، customer_name、email、phone، qr_transaction_number، status (pending/paid/cancelled)، created_at.  
4. *(اختياري)* جدول سلة مؤقتة إذا أردت تخزينها في DB؛ غير ضروري إذا استخدمنا Session أو LocalStorage مؤقتًا.  

**المخرجات:** رسم تخطيطي بسيط (ER diagram) أو نص SQL يحوي CREATE TABLE للجداول أعلاه.

### 3️⃣ تحديد بنية المجلدات والملفات (Folder Structure)  
```
/project-root
│
├── /assets               # الملفات الثابتة (صور، CSS، JS)
│   ├─ /images
│   ├─ /css
│   └─ /js
│
├── /includes             # ملفات PHP مشتركة يُستدعى في كل صفحة
│   ├─ config.php         # الإعدادات (DB، whistle numbers، base URL)
│   ├─ db.php             # دالة اتصال PDO وحيدة
│   ├─ helpers.php        # دوال مساعدة (html_escape، csrf_token، إلخ)
│   └─ auth.php           # فحص صلاحية الأدمن، بدء الجلسة
│
├── /admin                # لوحة التحكم
│   ├─ login.php
│   ├─ index.php          # dashboard
│   ├─ edit-course.php
│   ├─ orders.php
│   └─ … (أي ملفات أخرى CRUD)
│
├── /sql                  # ملفات قاعدة البيانات (schema.sql، ربما data.sql)
│
├── index.php             # متجر الواجهة الأمامية
├── cart.php
├── checkout.php
├── order-success.php
├─ process-payment.php    # AJAX endpoint لمعالجة دفع QR (مجرد استلام رقم العملية)
├─ cart-ajax.php          # AJAX لتحديث السلة
├─ setup.php              # إنشاء أول حساب أدمن (يُحذف بعد الاستخدام)
├─ .htaccess              # قواعد إعادة كتابة URL وحماية المجلدات
└─ README.md              # توثيق الإعداد والاستخدام
```

**المخرجات:** رسم شجري للمجلدات (يمكن كتابته في ملف `STRUCTURE.md`).

### 4️⃣ وضع مراحل التطوير (Milestones) وتتبع التقدم  
| المرحلة | الهدف | ما يُنجز |
|--------|-------|----------|
| **M0 – الإعداد** | تجهيز البيئة (Docker/LAMP)، استيراد DB، إنشاء ملفات الإعداد الأساسية. | `docker-compose` أو تعليمات تشغيل، `includes/config.php` فارغ، `sql/schema.sql` مُعد. |
| **M1 – واجهة المستخدم (Frontend)** | بناء صفحات المتجر الثابتة باستخدام HTML + Bootstrap فقط (لا منطق PHP بعد). | `index.php`، `cart.php`، `checkout.php`، `order-success.php` تعرضdummy data. |
| **M2 – ربط قاعدة البيانات** | تحويل الصفحات السابقة لاستخراج البيانات الفعلية من DB عبر PDO (عرض الدورة، إضافة للسلة عبر session). | منتجات تُقرأ من `courses`، السلة تُحفظ في `$_SESSION`. |
| **M3 – وظائف السلة dynami​c** | AJAX لإضافة/إزالة/تحديث cantidades دون reload. | `cart-ajax.php` يُحدث `$_SESSION['cart']` ويعيد JSON. |
| **M4 – checkout وعملية الدفع** | نموذج جمع بيانات العميل، عرض modal مع QR، حقل لإدخال رقم العملية. | `checkout.php` يحفظ الطلب في جدول `orders` بـ status=pending، يرقّـّـّــى لـ QR modal. |
| **M5 – تأكيد الدفع** | بعد أن يدخل العميل رقم العملية وتأكيده، يتم تحديث حالة الطلب إلى `paid` وإرسال إشعار واتساب (محاكاة أو استدعاء API بسيط). | `process-payment.php` يُحدّث `orders.status`، يرسل رسالة (يمكن أن يكون مجرد log أو استدعاء dummy API). |
| **M6 – لوحة التحكم** | بناء صفحات تسجيل الدخول، عرض الإحصائيات، تعديل الدورة، رفع صورة، عرض الطلبات وتعديل حالتها. | حماية بـ sessions + CSRF + bcrypt. |
| **M7 – الأمان والتشطيب** | مراجعة كل صفحة لاستخدام prepared statements، htmlspecialchars،かつ تجنّب مسارات مباشرة للملفات الحساسة. | إضافة .htaccess لحماية المجلدات، حذف `setup.php`، فحص سجلات الأخطاء. |
| **M8 – النشر والتوثيق** | كتابة README واضح مع خطوات إعداد Docker أو LAMP، توثيق المتغيرات في `config.php`. | تشغيل المشروع على بيئة جديدة ناجحًا. |

### 5️⃣ منهجية العمل اليومية (القيام بالمهام)  
1. **ابدأ بأصغر جزء يعمل** – مثلاً نسخة ثابتة من `index.php` تُظهر صورة الدورة وسعرها.  
2. **اختبره فورًا** – افتح المتصفح وتأكد من ظهوره بلا أخطاء.  
3. **أضف طبقة واحدة فقط** – اجلب البيانات من DB، وتأكد أن الاستعلام يعمل وأرجع النتائج المتوقعة.  
4. **قم بعمل commit** (إن كنت تستخدم Git) مع رسالة تصف ما أضفته بالضبط.  
5. **كرّر** للجزء التالي.  

بهذا الأسلوب تتجنب تراكم الأخطاء وتكون لديكalways نسخة شغّالة يمكن إظهارها للعميل أو للموجه في أي وقت.

### 6️⃣ أدوات وتقنيات مساعدة (بدون كتابة كود)  
- **الرسم التخطيطي** – استخدم draw.io أو甚至 ورقة قلم لتصميم схемات DB وتدفق المستخدم.  
- **قائمة المهام** – أداة مثل Trello، Notion أو ملف TODO.md بسيط لتتبع ما تم إنجازه وما تبقى.  
- **التوثيق أثناء السير** – بعد كل مرحلة أعدّ قراءة سريعة لـ README لتحديثه؛ يضمن عدم نسيان أي متغير بيئي أو خطوة إعداد.  
- **مراجعة الأمان** – بعد الانتهاء من ميزة ما، اسأل نفسك: "هل يمكن حقن SQL هنا؟ هل المخرجات مُفلترة؟ هل هناك توكن CSRF؟". احفظ الإجابة في ملف ملاحظات.  

### 7️⃣ الخلاصة  
**خطوات البداية من الصفر** هي:  

1. اكتب متطلبات واضحة (قائمة مهام المستخدم + متطلبات الأدمن + الأمان).  
2. صمم مخطط قاعدة البيانات بسيطًا.  
3. حدد بنية المجلدات التي تفصل بين الكود المشترك، الواجهة الأمامية، لوحة التحكم، والملفات الثابتة.  
4. ضع مراحل تطوير (M0…M8) بحيث كل مرحلة تنتهي بنسخة تعمل يمكنك اختبارها.  
5. اعمل بشكل تدريجي: ابدأ بواجهة ثابتة → połącz مع DB → أضف تفاعلات AJAX → أكمل عملية الدفع →ابنِ لوحة التحكم → Chamِل الأمان والنشر.  
6. توثّق كل خطوة واحفظ نسخًا احتياطية (أو استخدم Git) لتستطيع الرجوع أو مشاركة التقدم.  

بهذه الطريقة تبني المشروع خطوة بخطوة مع فهم عميق لكل جزء، مما يجعل الصيانة والتوسعات المستقبلية أسعارًا أسهل كثيرًا. إذا احتجت أي توضيح إضافي حول مرحلة معينة أو تريد مثالًا على صياغة متطلبات أو رسم تخطيطي، فقط أخبرني!
